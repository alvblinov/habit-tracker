# План 004 — Расписание по дням недели и статистика

## Контекст

Итерации 001–003 приняты и влиты в `main` (= `3587917`). Пользователь согласовал итерацию 004
(интервью 13.10.2026, `GOAL.md` → «Итерация 004», AC-23…AC-31): не все привычки ежедневные —
без расписания выходные рвут серию и занижают прогресс; статистика показывает общую картину
и учитывает расписание. Поведение привычек «каждый день» (все старые данные) не меняется.

После утверждения: план → `plans/004-schedule-stats.md`, ветка `feature/schedule-stats`,
прогон `implement` → `reports/004-schedule-stats/01/`, затем PR в `main`.

## Модель данных

У привычки новое поле `days` — отсортированный массив дней недели ISO (1 = пн … 7 = вс), 1–7 элементов.
Отсутствует/битое/пустое → все 7 дней (старые данные = «каждый день», AC-23, AC-31).
Ключ хранилища и `version: 1` не меняются. `addHabit` создаёт `days: [1..7]`.

## Логика (чистые функции, без DOM и без текущего времени)

| Файл | Что |
|---|---|
| `src/schedule.js` (новый) | `ALL_DAYS = [1..7]`; `WEEKDAY_SHORT` («пн»…«вс»), `WEEKDAY_FULL` («понедельник»…); `weekdayOf(key)` — ISO-день по локальной дате (`fromDateKey` из `src/dates.js`); `normalizeDays(raw)`; `isScheduled(habit, key)`; `describeDays(days)` → `''` для всех 7, иначе «пн, ср, пт». |
| `src/habits.js` | • `getStreak(habit, today)` — по правилам AC-24: старт с сегодня (если сегодня не отмечено — сегодня пропускается); назад по дням: отмечен → +1; по расписанию и не отмечен → стоп; выходной и не отмечен → пропуск. Остановка на дне раньше начала истории (первая отметка), чтобы цикл был конечным. • `getBestStreak(habit)` — проход от первой до последней отметки по тем же правилам (выходной без отметки не рвёт). Для «каждый день» результаты совпадают с прежними. • `getTodaySummary(state, today)` — AC-26: Y = назначенные на сегодня + отмеченные сегодня в выходной; X = отмеченные сегодня. • `updateHabit(state, id, { name, emoji, days })` — `days` через `normalizeDays`; пустой набор в UI не допускается (см. ниже); неизменённые значения → тот же объект. |
| `src/reminders.js` | `findDueReminders`: момент не срабатывает, если `!isScheduled(habit, toDateKey(at))` (AC-27, оба режима). |
| `src/storage.js` | `sanitizeHabit`: `days: normalizeDays(raw.days)`. |
| `src/stats.js` (новый) | `computeStats(state, todayKey, period)`, `period ∈ 7 \| 30 \| 'all'` → `{ percent, done, scheduled, totalMarks, bestWeekday, rows }`. Для привычки: начало = max(начало окна, начало истории = min(`createdAt`, первая отметка)); дни окна — с начала по вчера, плюс сегодня, если отмечено (AC-29). `scheduled` — дни по расписанию, `done` — из них отмеченные, `percent = done / scheduled` (`null`, если 0). `totalMarks` — все отметки в окне, включая выходные. Общий процент — сумма по привычкам. `bestWeekday` — ISO-день с наибольшим `done/scheduled` по всем привычкам за окно (ничья → более ранний день; нет данных → `null`). `rows`: `{ habitId, emoji, name, done, scheduled, percent, streak, best }`, сортировка по `percent` убыв. (`null` в конце), при равенстве — исходный порядок. |

## Интерфейс (`src/main.js`, `index.html`, `src/style.css`)

- **Форма ✏️**: под эмодзи — 7 переключателей `edit-day` (checkbox, `value` 1…7, подписи Пн…Вс),
  отмечены дни привычки. Снять последний отмеченный нельзя (чекбокс последнего дня `disabled`).
  Черновик `editDraft.days` — как name/emoji. Сохранение через `updateHabit`.
- **Карточка**: подпись `habit-days` («пн, ср, пт») рядом с названием; для всех 7 дней — не выводится.
- **Сетка**: клетка дня не по расписанию — класс `is-off` и `data-scheduled="false"` (бледнее), кликабельна;
  у остальных `data-scheduled="true"`.
- **Статистика**: кнопка «📊 Статистика» `stats-toggle` (aria-expanded) вверху; блок `stats-panel`
  (открыт/закрыт и период — в памяти модуля, по умолчанию закрыт и 30 дней):
  - период — три кнопки-радио `stats-period` (`data-period` 7 / 30 / all, aria-pressed);
  - `stats-percent` («Выполнено: 75%» или «—»), `stats-total` («Всего отметок: 12»),
    `stats-best-weekday` («Лучший день: среда» или «Лучший день: —»);
  - таблица: строки `stats-row` (`data-habit-id`) — эмодзи и название, процент + полоска `<meter>`/div,
    «N из M», «🔥 N», «🏆 M»;
  - без привычек — `stats-empty` «Добавьте привычку, чтобы увидеть статистику».
  - Блок перерисовывается в `render()` вместе со списком (отметка, правка, storage-событие).
- Весь пользовательский текст — через `textContent`. Существующие `data-testid` и тексты не меняются.
