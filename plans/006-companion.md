# План 006 — Помощник с выбором персонажа

## Контекст

По мотивам приложения Dear Me (бобёр-помощник) пользователь хочет дружелюбного помощника
с выбором персонажа (интервью 14.10.2026; `GOAL.md` → «Итерация 006», AC-41…AC-46).
7 персонажей — анимированные эмодзи Google Noto (🐱 Мурзик, 🦊 Алиса, 🐼 Пандуша, 🐸 Квака,
🦉 Софа, 🐧 Пин, 🦔 Колючка), без ИИ и внешних API: заранее написанные реплики подбираются по поводу.
Картинки уже скачаны координатором в `public/companions/` (7 SVG + 7 WebP, проверены, `ATTRIBUTION.md`).
Ветка `feature/companion` (от `feature/design`, PR #7 ещё не влит); прогон → `reports/006-companion/01/`.

## Логика (чистые функции, без DOM и без текущего времени)

`src/companion.js` (новый):
- `CHARACTERS` — 7 записей `{ id, emoji, code, defaultName, label }` (`id`: `cat|fox|panda|frog|owl|penguin|hedgehog`);
  `DEFAULT_CHARACTER = 'cat'`; `COMPANION_KEY = 'habit-tracker:companion'`; `MAX_NAME = 20`.
- `normalizeCompanionSettings(raw)` → `{ character, name, enabled, introduced }` (битое → по умолчанию,
  `introduced: false`; имя: trim, 1–20 символов, иначе — имя персонажа по умолчанию).
- `companionImage(id, { animated })` → `companions/<code>.webp|svg` (относительный путь).
- `partOfDay(hour)` → `morning (5–11) | day (12–17) | evening (18–22) | night`.
- `PHRASES[characterId][event]` — по 3+ варианта на повод в стиле персонажа (на «ты», тепло, без упрёков).
  Поводы: `greeting` (по части суток, + сводка «X из Y»), `mark`, `markStreak` (серия ≥ 2), `remaining` (осталось N),
  `allDone`, `newRecord`, `unmark`, `empty`, `poke`, `intro` (представление после выбора).
- `pickPhrase(event, ctx, characterId, rand)` → строка с подстановками `{name}`, `{habit}`, `{streak}` (+ склонение
  «день/дня/дней»), `{left}`, `{done}`, `{total}`; `rand` передаётся (в тестах — детерминированный).
- `companionEventForMark({ before, after, today })` — чистое определение повода после отметки по состоянию до/после:
  `newRecord`, `allDone`, `remaining`, `markStreak`, `mark`; для снятия — `unmark`.

## Интерфейс (`src/main.js`, `index.html`, `src/style.css`)

- **Шапка**: кнопка-персонаж `companion` (~64px, WebP; при `prefers-reduced-motion` — SVG), `aria-label`
  «Помощник {name}». Облачко `companion-bubble` (`role="status"`, `aria-live="polite"`), текст через `textContent`,
  скрывается через ~6 с; новая реплика заменяет прежнюю.
- **Меню** по клику на персонажа (`companion-menu`): реплика `poke` + «Сменить помощника» (`companion-change`),
  «Переименовать» (`companion-rename`, поле `companion-name-input`, maxlength 20, пустое не сохраняется),
  «Выключить помощника» (`companion-off`). Esc / клик вне — закрыть.
- **Выключен**: персонажа и облачка нет; в шапке маленькая кнопка «Включить помощника» (`companion-on`).
- **Знакомство** `companion-intro` — **встроенная карточка над формой добавления, не модальное окно**: не блокирует
  страницу (иначе все прежние e2e на чистом localStorage упёрлись бы в оверлей). 7 вариантов `companion-option`
  (`data-character`, картинка и имя), кнопка «Позже» (`companion-intro-skip` → Мурзик). Заголовок: без привычек —
  «Привет! Я буду помогать тебе с привычками. Кого выберешь?», с привычками — «У нас новенький — выбери себе
  помощника!». Показ — пока `introduced: false`; после выбора/«Позже» — `introduced: true` и реплика `intro`.
- **Поводы**: при загрузке — `greeting` (или `empty`, если привычек нет), после знакомства; при отметке/снятии
  сегодняшнего дня (кнопка или клетка) — по `companionEventForMark`; клик по персонажу — `poke`.
- Картинки персонажей в карточке знакомства — SVG; анимирован только помощник в шапке.
- Подпись в подвале: «Эмодзи и персонажи: Google Noto …». README: раздел «Помощник».

## Тесты (demo-test-writer)

- `tests/unit/companion.test.js`: 7 персонажей, пути, `normalizeCompanionSettings`, `partOfDay` (границы),
  полнота `PHRASES` (все поводы у всех, ≥ 3 варианта, после подстановки нет `{…}`, нет слов-упрёков

- `tests/e2e/companion.spec.js`: AC-41 (карточка знакомства, выбор и reload, «Позже» → Мурзик, старые данные →
  «У нас новенький», нет повторного показа), AC-42 (WebP в шапке / SVG при reduced motion; смена, переименование,
  пустое имя, выключение — после reload), AC-43 (облачко на загрузке, на отметке с названием, «осталось», «всё

- Прежние тесты не меняются; если какой-то упрётся в новую разметку — сообщить, не подгонять.

## Не входит

ИИ и внешние API, звук, вводный опрос, библиотека привычек, дыхание, дневник настроения, новые зависимости.

## Проверка

1. `npm run test:unit`, `npm run test:e2e` (координатор вне песочницы), `npm run build` (`dist/companions/` — 14 картинок).
2. Аудит → `reports/006-companion/01/audit.md`, PASS.
3. Просмотр координатором во встроенном браузере (знакомство, реплики, тёмная тема, телефон).
4. Ручная приёмка: первое открытие (вкладка инкогнито), выбор, реплики на отметку/всё выполнено, меню, выключение, F5.
5. После приёмки — STATUS.md, коммит в `feature/companion`, PR в `main` (после слияния PR #7).

# Расширение (прогон 03): помощник-тренер и гид

## Контекст

Прогоны 01–02 прошли (аудит PASS). При просмотре пользователь (15.10.2026) отметил: помощник не хвалит
добавление привычки; сверху его не видно при заполнении клеток; облачко неприметное и скучное; роль неясна.
Согласовано расширение — `GOAL.md`, «Расширение итерации 006», AC-47…AC-54; заодно — фикс пустеющих плашек
анимированных эмодзи (💧: первые и последние кадры анимации прозрачные). PR #7 влит, `main` = `0a8e56f`.
Прогон: `reports/006-companion/03/`.

## Логика (чистые функции)

- `src/companion.js`:
  - новые поводы в `PHRASES` (у всех 7 персонажей, ≥ 3 варианта, без упрёков и без дословных совпадений
    между персонажами): `added`, `firstHabit`, `markPast`, `firstDayClosed`, `milestone` (`{streak}` для
    3/7/14/30/50/100), `reminderSet`, `edited`, `deleted` (мягко), `tourOffer`, `tipIntro`;
  - `STREAK_MILESTONES = [3, 7, 14, 30, 50, 100]`; `companionEventForMark` дополняется: отметка прошлого дня →
    `markPast`; серия достигла вехи → `milestone` (приоритет: `milestone` > `newRecord` > `allDone` > …);
  - `ACCENTS[characterId]` — ключ акцентного цвета (оранжевый у лисы, зелёный у лягушки и т. д.; цвета —
    в CSS-переменных для светлой и тёмной темы).
- `src/companion-qa.js` (новый): `QA` — ~40 записей `{ id, keywords[], answer(characterId) | answers{...}, quick? }`
  (как пользоваться трекером и советы по привычкам); `normalizeQuestion(text)` (нижний регистр, ё→е, без знаков);
  `findAnswer(text)` → запись по максимальному совпадению ключевых слов или `null`; `QUICK_QUESTIONS` (6–8 кнопок);
  ответ на неизвестный вопрос — по персонажу с подсказкой тем.
- `src/companion-tips.js` (новый): `TIPS` (~30 советов); `tipForDay(dateKey)` — детерминированно по дате;
  `shouldShowTip(settings, todayKey)` (поле `lastTipDate` в настройках помощника).
- `src/companion-tour.js` (новый): `TOUR_STEPS` — 6 шагов `{ target: data-testid/селектор, title, text }`.
- `normalizeCompanionSettings` дополняется полями `tourOffered`, `lastTipDate` (битое → по умолчанию).

## Интерфейс

- **Место**: виджет `companion-dock` — `position: fixed`, правый нижний угол (отступы 16px, safe-area), z-index
  выше карточек; персонаж ~64px (на узком экране ~52px); облачко — над ним, справа выровнено. У страницы
  `padding-bottom` на высоту виджета, чтобы последние элементы можно было прокрутить выше помощника.
  Облачко `pointer-events: none`, кроме кнопки «закрыть»; персонаж кликабелен. Кнопка «Включить помощника»
  в выключенном состоянии остаётся в шапке. Прежние `data-testid` помощника сохраняются.
- **Облачко** `companion-bubble`: заголовок `companion-bubble-name` (имя), текст `companion-bubble-text`, кнопка
  `companion-bubble-close`; цветная рамка/тень в акценте персонажа (`data-accent`), хвостик к персонажу (CSS-
  треугольник), появление `scale+fade` с пружиной, «печать» текста по буквам (~25 мс/символ, полный текст в
  `aria-label`/`data-full-text` сразу; `textContent` наращивается — без innerHTML), персонаж подпрыгивает.
  При reduced motion — без анимаций, текст сразу. Время показа = max(6 с, время печати + 4 с).
- **Конфетти** на вехах: 30–40 кусочков CSS-анимации в цветах палитры внутри виджета, ~1.5 с, `aria-hidden`,
  удаляются после; при reduced motion — нет.
- **Поводы**: добавление (`added`/`firstHabit`), любая клетка/кнопка (`mark`/`markPast`/`unmark`/`remaining`/
  `allDone`/`firstDayClosed`/`newRecord`/`milestone`), сохранение напоминания (`reminderSet`), сохранение ✏️ (`edited`),
  удаление (`deleted`). Таймеры не вызывают полную перерисовку.
- **Меню** (`companion-menu`) дополняется: «Спроси меня» (`companion-ask-input`, `companion-ask-submit`, кнопки
  `companion-quick-question`), «Экскурсия» (`companion-tour-start`). Ответ — в облачке (повод `answer`, `data-event`).
- **Экскурсия** `companion-tour`: затемнение страницы с «окном» вокруг цели (подсветка через box-shadow),
  карточка шага рядом (`companion-tour-step`, «Шаг N из 6», «Назад»/«Далее»/«Закрыть»), прокрутка к цели;
  если цели нет (например, нет привычек) — шаг объясняет без подсветки. Esc — закрыть. Предлагается облачком
  с кнопкой «Покажи!» после знакомства (`tourOffered: true`), из меню — всегда.
- **Совет дня**: при загрузке, если включён и `lastTipDate ≠ сегодня` — после приветствия показывается совет
  (`data-event="tip"`), `lastTipDate` сохраняется.
- **Капля** (итерация 005): у плашки `habit-emoji` с анимированной картинкой — статичная SVG того же эмодзи
  фоном (`background-image` на обёртке или вторая `img` под WebP), чтобы прозрачные кадры не давали пустоты.
  `textContent` и прочие проверки `habit-emoji` не меняются (ровно одна `img.emoji-img` — если фон делается
  второй картинкой, она без класса `emoji-img`; лучше — CSS-фон).
- README: раздел «Помощник» — новые возможности.

## Решение пользователя по прогону 04 (15.10.2026)

Аудит 04 — повторный FIX по просмотру координатора: (а) содержимое меню помощника шире рамки (горизонтальная
прокрутка, кнопка «Спросить» обрезана); (б) облачко на телефоне ~6 с закрывает правые клетки сетки. Пользователь
разрешил цикл 05 и выбрал вариант «плашка внизу»:
- ≤ 420px: реплика — компактная плашка в нижней полосе экрана слева от персонажа (`position: fixed; left: 12px;
  right: ~72px; bottom: 12px`, высота ограничена, длинный текст — до 3 строк с прокруткой внутри, хвостик вправо к
  персонажу); полоса освобождена нижним отступом страницы — плашка не закрывает клетки и кнопки;
- шире: облачко над персонажем, но если справа от колонки контента есть место — облачко не заходит на карточки
  (ширина/сдвиг ограничены свободным полем справа); если места нет — как сейчас, с `pointer-events: none`;
- меню: колонка `minmax(0, 1fr)`, поле вопроса `flex: 1 1 0; min-width: 0`, кнопка `flex: 0 0 auto`, без
  горизонтальной прокрутки.
Тесты: e2e — у меню `scrollWidth <= clientWidth`, кнопка «Спросить» целиком видна (1100 и 380px); на 375×700 облачко
не пересекается с только что отмеченной клеткой и с кнопками карточки; на 1100px облачко не пересекается с карточками,
если есть свободное поле. Прогон: `reports/006-companion/05/`.
