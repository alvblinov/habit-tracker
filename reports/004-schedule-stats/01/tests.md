## Расхождение для аудитора: лучший день без единой отметки

GOAL: «лучший день недели (наибольший процент выполнения; «—», если данных нет)», AC-30: «нет данных → «—»».
Implementer: если в периоде есть дни по расписанию, но нет ни одной отметки, все дни недели имеют 0%,
и по правилу ничьей выбирается понедельник («Лучший день: понедельник»).

Моё прочтение: при 0% во всех днях выполнения нет, «лучшего» дня не существует, а понедельник — артефакт
правила ничьей и вводит пользователя в заблуждение. Поэтому тесты ожидают «—» / `null`:

- unit: `stats.test.js` → «лучший день недели (AC-30)» → «дни по расписанию есть, но ни одной отметки за период → нет лучшего дня»;
- e2e: `schedule-stats.spec.js` → «дни по расписанию есть, но ни одной отметки за период → «Лучший день: —»».

По коду эти два теста, скорее всего, упадут. Решение (исправить код или принять прочтение implementer’а
и изменить ожидание) — за аудитором/пользователем; тест не подстраивался под реализацию.

## Прочие допущения (из плана/implementation.md, не из GOAL)

- `percent` — проценты 0…100 (`implementation.md`); в unit для неровных долей используется
  `toBeCloseTo(done*100/scheduled, 0)`, то есть подходит и округление до целого, и точное значение.
  Точные значения (`100`, `75`, `50`, `0`) проверяются только на ровных долях. В e2e данные подобраны так,
  чтобы проценты были целыми (50/100/30/75).
- Ничья в лучшем дне проверена на случае, где «раньше по неделе» и «раньше по календарю» совпадают (ср vs пт),
  чтобы не зависеть от трактовки «более ранний день».
- Пустой `days` в `updateHabit` → все 7 дней (план: «пустое → все 7»); в UI снять последний день нельзя
  (проверяется `disabled` + число отмеченных = 1, по плану).
- Строки «Выполнено: —», «Лучший день: —», «Добавьте привычку, чтобы увидеть статистику», скрытие `#stats-table` — из плана.
