## По пунктам плана

### Модель данных
- `days` — отсортированный массив ISO-дней 1…7. `normalizeDays`: не массив / нет валидных значений → `[1..7]`;
  значения вне 1…7 и повторы отбрасываются. `addHabit` создаёт `days: [1..7]`. Ключ хранилища и `version: 1` прежние.

### `src/schedule.js`
- `weekdayOf(key)` — через `fromDateKey` (локальная дата), `getDay()` 0 → 7.
- `isScheduled(habit, key)` — по `normalizeDays(habit.days)`, т.е. привычка без `days` назначена на все дни.
- `describeDays` → `''` для 7 дней, иначе «пн, ср, пт».

### `src/habits.js`
- `getStreak` / `getBestStreak` — правила AC-24: отмеченный день +1; день по расписанию без отметки рвёт серию;
  выходной без отметки пропускается; сегодня без отметки не рвёт.
  Реализация идёт по отсортированным отметкам и проверяет промежуток между соседними отметками
  (`gapHasScheduledDay`): цикл по промежутку не длиннее 7 шагов (за 7 дней подряд встречается любой день
  недели, а в расписании хотя бы один день). Итог эквивалентен плановому «идём назад по дням до начала
  истории», но число шагов не зависит от длины пропусков. Отметки позже `todayKey` в серии не учитываются.
  Для «каждый день» любой непустой промежуток содержит день по расписанию → результаты совпадают с прежними.
  `getBestStreak` не мутирует `habit.done`.
- `getTodaySummary` — `total` = назначенные на сегодня + отмеченные сегодня; `done` = отмеченные сегодня.
- `updateHabit(state, id, { name, emoji, days })` — `days` через `normalizeDays`; если `days` не передан,
  поле не трогается (и не добавляется). Неизменённые name/emoji/days (с учётом нормализации, напр.
  `[5,3,1]` = `[1,3,5]`) → тот же объект состояния.

### `src/reminders.js`
- Фильтр встроен в поиск момента: в режиме «Каждые N» момент учитывается только если
  `isScheduled(habit, toDateKey(new Date(at)))`; в режиме «В определённое время» дни не по расписанию
  пропускаются так же, как уже отмеченные. Это точнее, чем отбрасывать уже найденный последний момент:
  более ранний момент окна в день по расписанию не теряется (на практике при окне ≤ 5 мин результат тот же).

### `src/storage.js`
- `days: normalizeDays(raw.days)` — старые данные и битые `days` → все 7 дней.

### `src/stats.js`
- Окно: 7 → сегодня−6…сегодня; 30 → сегодня−29…сегодня; `'all'` → без нижней границы; неизвестный период → 30.
- Для привычки: начало = max(начало окна, min(`createdAt`, первая отметка ≤ сегодня)). Дни по расписанию
  с начала по вчера считаются арифметически по дням недели (без перебора дней — окно «Всё время» может
  быть длинным); сегодня добавляется к `scheduled`, только если отмечено и назначено.
- `done` — отметки в [начало, сегодня] в дни по расписанию; `totalMarks` — все отметки в [начало, сегодня],
  включая выходные. Отметки позже сегодня не учитываются.
- `percent` — **целое число 0…100** (`Math.round(done*100/scheduled)`), `null`, если `scheduled = 0`
  (в плане формула `done / scheduled` без указания шкалы — выбрана шкала процентов для вывода «75%»).
- `bestWeekday` — ISO-день с наибольшим `done/scheduled` (точное сравнение через перекрёстное
  умножение), ничья → более ранний день, нет дней по расписанию → `null`.
- `rows` — `{ habitId, emoji, name, done, scheduled, percent, streak, best }`; сортировка по
  `percent` (округлённому) по убыванию, `null` в конце, при равенстве — исходный порядок.

### Интерфейс
- Форма ✏️: под эмодзи `fieldset.edit-days` с 7 чекбоксами `edit-day` (`value` 1…7, подписи Пн…Вс,
  `title` — полное название). Если отмечен один день, его чекбокс `disabled`; дополнительно обработчик
  не даёт снять последний день. Черновик `editDraft.days`; сохранение через `updateHabit`.
  Переключение дней не перерисовывает список (меняется только `disabled`), фокус не теряется;
  `captureFocus` различает чекбоксы по `value`.
- Карточка: `span.habit-days` (`data-testid="habit-days"`) в заголовке после названия; для 7 дней не выводится.
- Сетка: `data-scheduled="true|false"` у каждой клетки, класс `is-off` у выходных (бледнее, штриховка),
  клик работает как раньше; к `aria-label`/`title` выходной клетки добавляется « — выходной»
  (у клеток «каждый день» подпись прежняя).
- Статистика: статическая разметка в `index.html` после `<h1>`: кнопка «📊 Статистика»
  (`stats-toggle`, `aria-expanded`, `aria-controls`), `section#stats-panel` (`hidden` по умолчанию),
  три кнопки `stats-period` (`data-period` 7/30/all, `aria-pressed`, по умолчанию 30), `stats-percent`
  («Выполнено: 75%» / «Выполнено: —»), `stats-total` («Всего отметок: N»), `stats-best-weekday`
  («Лучший день: среда» / «Лучший день: —»), таблица (`tbody` со строками `stats-row`, `data-habit-id`:
  эмодзи и название, процент + `<meter>`, «N из M», «🔥 N», «🏆 M»), `stats-empty`
  «Добавьте привычку, чтобы увидеть статистику» (таблица скрыта). Общие цифры при пустом списке
  выводятся с «—»/0.
  Открытость и период — переменные модуля; `renderStats` вызывается из `render()` (отметка, правка,
  storage-событие, focus). Кнопки периода не пересоздаются, поэтому фокус на них сохраняется.
- Пользовательский текст (названия, эмодзи) — только `textContent`. Существующие `data-testid` и тексты не менялись.

## Отклонения от плана

- `getStreak`/`getBestStreak`: обход по отметкам с проверкой промежутков (≤ 7 шагов) вместо обхода
  каждого дня до начала истории — та же семантика, конечный и короткий цикл.
- `findDueReminders`: фильтр расписания применяется при поиске момента, а не к уже найденному моменту (см. выше).
- `percent` в `computeStats` — целые проценты 0…100 (уточнение формата, не изменение правила).
- В `stats.js` экспортированы `PERIODS` и `DEFAULT_PERIOD` (вспомогательные константы).
