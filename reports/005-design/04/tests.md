## Изменение требования (явно)

AC-38 изменён **решением пользователя 14.10.2026** (вариант «двигаются всегда»). Прежние ожидания
теста AC-38 — «WebP ~2 с только после отметки, затем снова SVG», атрибут `data-animating`,
«WebP не грузится до отметки» — относятся к прежней редакции требования и **удалены как устаревшие**,
а не ослаблены. Новые ожидания взяты из `GOAL.md` (AC-38) и плана, а не из кода.

## Изменённые файлы

- `tests/e2e/design.spec.js` — блок AC-38 переписан полностью; добавлены хелперы `ANIMATED`,
  `tagCardImg`/`cardImgTag` (пометка `<img>` JS-свойством для проверки идентичности элемента),
  `isAnimatedWebp` (разбор RIFF: блок `ANIM` и ≥ 2 кадров `ANMF`); обновлён комментарий `openWithClock`.
  Блоки AC-32…AC-35, AC-37, AC-39, AC-40 не менялись.
- `tests/e2e/habits.spec.js:145` — `src` картинки ⭐ на карточке: `emoji/2b50.svg` → `emoji/2b50.webp`.
- `tests/e2e/edit-best-streak.spec.js:394` — `src` картинки 📚 на карточке: `emoji/1f4da.svg` → `emoji/1f4da.webp`.

Последние две правки — места, где прежние тесты (уточнённые решением по прогону 02) требовали SVG
**на карточке**; по новой редакции AC-38 карточка без reduced motion (в Playwright по умолчанию
`no-preference`) показывает WebP. Остальные проверки этих тестов (нет `b`, `img[src="x"]`, ровно одна
картинка в месте эмодзи) не тронуты. `schedule-stats.spec.js:518` (статистика) остаётся `.svg`.

Тесты AC-37 в `design.spec.js` не менялись: они выполняются при `reducedMotion: 'reduce'`, где
по новой редакции на карточках по-прежнему SVG, поэтому их ожидания остаются верными. Unit-тесты
`emoji-assets` не затрагивались.

## Соответствие критериям (AC-38, новая редакция)

| Требование | Тест (`design.spec.js`, describe «…движутся всегда, «подпрыгивание» при отметке (AC-38)») |
|---|---|
| Карточки: WebP сразу после загрузки для 9 эмодзи, SVG для 🏃 🧘 💊; без отметки эффекта нет | «сразу после загрузки на карточках 9 эмодзи — анимированные WebP…» (все 12, `data-bounce` отсутствует, WebP-файлы действительно анимированные, запрошены ровно 9 WebP) |
| Формы добавления, ✏️ и статистика — SVG | тот же тест (все 12 в каждом месте; карточка при открытой ✏️ остаётся WebP) |
| Кнопка «Сегодня» → `data-bounce="true"` и `is-bounce` (~600 мс), затем снимаются | «кнопка «Сегодня» для 📚…» (есть при 0 и 300 мс, CSS-анимация ≠ none, снято после 700 мс; другая привычка без эффекта; отметка/серия/данные на месте) |
| Клетка сегодняшнего дня → эффект | «клик по сегодняшней клетке тоже даёт «подпрыгивание»…» |
| 🏃 🧘 💊: SVG + эффект | «🏃, 🧘, 💊: на карточке статичный SVG…» (WebP не запрашивается) |
| Снятие отметки — без эффекта; снятие сразу после отметки прекращает эффект | «снятие отметки (кнопкой и клеткой)…» |
| Отметка прошлого дня — без эффекта | «отметка прошлого дня эффекта не даёт» (вчера, воскресенье) |
| reduced motion → SVG на карточках, без эффекта | «при prefers-reduced-motion: reduce…» (до/после отметки SVG, `animationName: none`, ни одного WebP-запроса) |
| `<img>` карточки не пересоздаётся при том же `src` | «<img> карточки не пересоздаётся…»: идентичность 📚 (WebP) и 🏃 (SVG) после отметки другой привычки, окончания её эффекта (перерисовка по таймеру), отметки прошлого дня, тика напоминаний (16 с), события `focus`, смены темы, открытия статистики; а также в тестах кнопки/клетки — тот же элемент во время и после собственного эффекта. Обратная проверка: смена эмодзи в ✏️ на 🎸 даёт новый элемент с `1f3b8.webp` |
| Внешних запросов нет, ошибок страницы нет | во всех тестах с `collectRequests`/`collectErrors` |

Все тесты AC-38 используют управляемые часы (`page.clock.install` + `pauseAt`), таймер эффекта
срабатывает только по `runFor`, поэтому проверки «есть эффект» / «снят» детерминированы.

## Сознательно не покрыто

- Визуальное впечатление от движения WebP и «подпрыгивания» — проверяется глазами при ручной приёмке
  (автотест проверяет `src`, анимированность файла и наличие CSS-анимации, но не вид).
- Переключение настройки reduced motion во время работы страницы (по implementation.md применяется
  при следующей перерисовке; в требованиях не оговорено).
- Перезапуск анимации WebP в пикселях — недоказуем без покадрового анализа; доказывается косвенно
  идентичностью `<img>`.
