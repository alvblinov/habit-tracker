## Замечания

### 1. BLOCKER — design.spec.js:427 (AC-33 light): гонка с перерисовкой по таймеру «подпрыгивания»; причина — `src/main.js:111` (`render()` в таймере `startEmojiBounce`)

- Проблема. Тест (без reduced motion, часы `setFixedTime` — таймеры идут реально) нажимает «Сегодня» у `c`
  (design.spec.js:394) → `startEmojiBounce('c')` ставит `setTimeout(render, 600)`. `render()` всегда вызывает
  `renderStats(today)` (main.js:1103), который пересоздаёт все `stats-row`. Через ~600 мс после клика тест как раз
  открывает статистику и меряет `usedColors`. `locator.evaluate` — два шага (найти элемент, выполнить функцию);
  если между ними строки перерисованы, функция получает отсоединённый `<tr>`, у которого `getComputedStyle`
  возвращает пустые строки, поэтому массив пустой (`Received array: []`). В итоговом снимке страницы всё верно,
  цвета на месте. Это не регрессия стилей: CSS строки и код статистики не менялись. В прогоне 03 таймер срабатывал
  через 2000 мс, уже после замера, а с 600 мс попадает в окно проверки. Поэтому dark прошёл, а light нет: падение
  нестабильное.
- Последствие. Тест падает нестабильно. Для пользователя через 0,6 с после каждой отметки полностью перерисовываются
  карточки и статистика, хотя нужно только снять класс. Это лишняя работа и тот же риск для любых других тестов,
  которые что-то измеряют в первые ~0,6 с после отметки.
- Исправление (приложение, предпочтительно). В колбэке таймера `startEmojiBounce` (main.js:107-112) не вызывать
  `render()`. Вместо этого точечно снять эффект с текущей карточки:
  ```js
  bounceTimer = setTimeout(() => {
    const id = bounceHabitId;
    bounceTimer = null;
    bounceHabitId = null;
    const plate = listEl.querySelector(`.habit-card[data-habit-id="${CSS.escape(id)}"] .habit-emoji`);
    if (plate) { delete plate.dataset.bounce; plate.querySelector('.emoji-img')?.classList.remove('is-bounce'); }
  }, EMOJI_BOUNCE_MS);
  ```
  Тесты AC-38 («снято после 700 мс», идентичность `<img>`) это поведение по-прежнему проверяют. Ожидание
  в tests.md «перерисовка по таймеру» нужно будет убрать или переформулировать: идентичность `<img>` после
  окончания эффекта остаётся верной.
  Дополнительно (тест) можно сделать замер устойчивым:
  `await expect.poll(() => usedColors(statsRow(page, 'b'))).toContain(opaque(bButton))` (то же для rowA).

### 2. BLOCKER — design.spec.js:994 (AC-38, тест :960): проверка несуществующего элемента, дефект теста

### 3. BLOCKER — design.spec.js:940-947 (AC-37, «эмодзи вне набора… ⭐»): устаревшее ожидание, дефект теста

- Проблема. В этом тесте нет `emulateMedia({ reducedMotion: 'reduce' })`, в отличие от двух соседних тестов AC-37.
  Утверждение tests.md, что все тесты AC-37 выполняются при reduce, неверно. По умолчанию в Playwright стоит
  `no-preference`, поэтому по новой AC-38 карточка показывает `emoji/2b50.webp`. Приложение работает правильно:
  неизвестный символ заменяется на ⭐, а `cardEmojiUrl` возвращает WebP.
- Последствие. Тест падает при корректном поведении.
- Исправление (тест, design.spec.js:946). Заменить проверку на `await expectNotoImage(habitEmoji(page, 'a'), '⭐', { animated: true });`,
  так же как сделано в habits.spec.js:145. Другой вариант — добавить `await page.emulateMedia({ reducedMotion: 'reduce' })`
  в начало теста. Первый вариант лучше: он заодно проверяет fallback в режиме по умолчанию.
  Исправление в tests.md (неверное утверждение о reduce) тоже стоит отметить.
