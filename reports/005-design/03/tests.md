## 1. Хелпер `expectNotoImage` / `emojiImage` (design.spec.js, замечание 1 аудита)

Раньше размер текстового узла мерился через `Range.getBoundingClientRect()`. Эта рамка не учитывает
`overflow`/`clip` предка, поэтому проверка всегда срабатывала ложно.

Теперь каждый непустой текстовый узел внутри элемента эмодзи проверяется так:
- контейнер `n.parentElement.closest('.visually-hidden')` найден;
- рамка контейнера `getBoundingClientRect()` не больше 1×1;
- `getComputedStyle(контейнер)`: `overflow === 'hidden'` и `position === 'absolute'`.

Если хотя бы одно условие не выполнено, ставится `visibleText = true` и тест падает. Поэтому символ,
выведенный обычным текстом рядом с картинкой, по-прежнему будет пойман.

Остальные поля хелпера и ожидания `expectNotoImage` не менялись: одна картинка, `src`, тот же адрес,
`decode()`, `complete`, ответ сервера, тип, размер больше 0, `textContent` равен символу.
Тесты AC-37…AC-40 тоже не менялись.

Другие места `design.spec.js` проверены: `createRange` и рамка `Range` больше нигде не используются.
`getBoundingClientRect` остался только для рамки самой `<img>`, и там он корректен.

## Сознательно не покрыто

- Визуальная обрезка `clip: rect(0 0 0 0)` отдельно не проверяется: достаточно `overflow: hidden`,
  `position: absolute` и рамки ≤ 1×1, как предложил аудит.
- Внешний вид (пятна, анимация WebP) автотесты не подтверждают — нужна ручная приёмка.
