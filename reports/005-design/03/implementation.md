## Что проверено в коде

### Замечание 1: «символ рисуется системным шрифтом» (`expectNotoImage`)
- `src/main.js:135-154`, `renderEmoji`: создаётся `<img class="emoji-img" alt="" aria-hidden="true">` и
  `span.visually-hidden`. Символ записывается в span через `textContent`. Других текстовых узлов в результате нет.
- `renderEmoji` используется в четырёх местах: форма добавления (`main.js:223`), форма ✏️ (`:533`),
  плашка карточки (`:283`), строка статистики (`:929`). Ни в одном из них символ не выводится отдельным текстом.
- `src/style.css:302-312`, `.visually-hidden`: `position: absolute; width/height: 1px; overflow: hidden;
  clip: rect(0 0 0 0); white-space: nowrap`. Для `.habit-emoji` (`:662`), `.stats-emoji` (`:328`)
  и `.emoji-option-face` (`:579`) нет правил, которые перебивают эти свойства у вложенного span.
  Правила для `.emoji-img` касаются только картинки.
- Вывод: видимого символа нет. Тест ложно срабатывает, потому что `Range.getBoundingClientRect()`
  не учитывает `overflow`/`clip` предка. Приложение исправлять не нужно.

### Замечание 2: три прежних теста ожидают 0 `<img>` в карточке и строке статистики
- В карточке и строке статистики ровно одна картинка — `img.emoji-img` из `renderEmoji`. Её требует AC-37.
- Название выводится через `textContent`: `main.js:287` (`name.textContent = habit.name`) и
  `:932` (`name.textContent = row.name`). В `src/` нет ни одного `innerHTML` (проверено `grep -rn innerHTML src/`).
  Значит, внедрить разметку через название нельзя.
- Вывод: ожидания тестов противоречат AC-37. Пользователь разрешил уточнить их (решение по прогону 02).
  Приложение исправлять не нужно.
