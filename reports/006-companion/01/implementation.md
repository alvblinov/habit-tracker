## По пунктам плана

### Логика — `src/companion.js` (без DOM, без текущего времени)

- `CHARACTERS` — 7 записей `{ id, emoji, code, defaultName, label }`:
  `cat 🐱 1f431 Мурзик Кот`, `fox 🦊 1f98a Алиса Лиса`, `panda 🐼 1f43c Пандуша Панда`, `frog 🐸 1f438 Квака Лягушка`,
  `owl 🦉 1f989 Софа Сова`, `penguin 🐧 1f427 Пин Пингвин`, `hedgehog 🦔 1f994 Колючка Ёжик` (бобра нет).
  `DEFAULT_CHARACTER = 'cat'`, `COMPANION_KEY = 'habit-tracker:companion'`, `MAX_NAME = 20`.
- Дополнительно экспортируются вспомогательные: `getCharacter(id)` (неизвестный → кот), `normalizeCompanionName(raw)`
  (trim, 1–20 символов, иначе `null`), `defaultCompanionSettings()`, `pluralDays(n)`, `pluralHabits(n)`,
  `EVENTS` (список поводов), `HELLO` (приветствие по части суток для каждого персонажа).
- `normalizeCompanionSettings(raw)` — принимает объект или JSON-строку; битое/отсутствующее → `{ character: 'cat',
  name: 'Мурзик', enabled: true, introduced: false }`; неизвестный персонаж → кот; имя вне 1–20 символов после trim →
  имя персонажа по умолчанию; `enabled` ложно только при `false`; `introduced` истинно только при `true`.
- `companionImage(id, { animated })` → `companions/<code>.webp` или `companions/<code>.svg` (относительный путь).
- `partOfDay(hour)` → `morning` 5–11, `day` 12–17, `evening` 18–22, `night` 23–4; нецелое/вне 0–23 → `day`.
- `PHRASES[characterId][event]` — у каждого из 7 персонажей по каждому из 10 поводов 3 варианта (у кота на `poke` — 4),
  всего 211 реплик. На «ты», без глаголов прошедшего времени с родом по отношению к пользователю, без упрёков.
- `pickPhrase(event, ctx, characterId, rand = Math.random)` — индекс `floor(rand() * n)` (rand ≤ 0 / не число → 0,
  ≥ 1 → последний). Подстановки: `{name}` (имя помощника, при пустом — имя персонажа по умолчанию), `{habit}`
  (по умолчанию «привычка»), `{streak}` → «N день/дня/дней», `{left}` → «N привычка/привычки/привычек», `{done}`,
  `{total}`, `{hello}` — приветствие персонажа по части суток (`ctx.part` или `ctx.hour`). Подстановка в один проход:
  текст из названия привычки (например, `{name}`, `$&`, HTML) повторно не разбирается. Неизвестный повод → `''`,
  неизвестный персонаж → кот.
- `companionEventForMark({ before, after, today, habitId? })` → `null`, если сегодняшняя отметка этой привычки
  (или, без `habitId`, любой) не изменилась; иначе `{ event, ctx: { habit, streak, left, done, total } }`. Порядок:
  1. `unmark` — отметку сняли;
  2. `newRecord` — серия ≥ 2, равна лучшей серии и лучшая серия выросла (по сравнению с `before`);
  3. `allDone` — `done === total > 0` (сводка дня `getTodaySummary`);
  4. `remaining` — осталось 1–2 привычки;
  5. `markStreak` — серия ≥ 2;
  6. `mark` — иначе.

### Интерфейс

- **Шапка**: блок `companion-slot` между заголовком и кнопкой темы. Кнопка `companion` (64 px, на ≤ 420 px — 52 px),
  `aria-label`/`title` «Помощник {name}», `data-character`; картинка — WebP, при `prefers-reduced-motion: reduce` — SVG
  (смена настройки отслеживается). До знакомства помощника в шапке нет.
- **Облачко** `companion-bubble` (`role="status"`, `aria-live="polite"`, `data-event` = повод) — под персонажем,
  абсолютно позиционировано, `pointer-events: none` (не перехватывает клики). Текст — `textContent`. Новая реплика
  заменяет прежнюю и перезапускает таймер; через 6000 мс облачко скрывается. Таймер меняет только `hidden` облачка —
  `render()`/список не перерисовываются (урок 005-04).
- **Меню** `companion-menu` по клику на персонажа (и реплика `poke` в облачке); повторный клик, Esc (фокус
  возвращается на персонажа) или pointerdown вне помощника — закрывают.
  - «Сменить помощника» `companion-change` → подпанель `companion-picker` из 7 кнопок `companion-pick`
    (`data-character`, SVG, `aria-pressed` у текущего). Выбор другого персонажа ставит его имя по умолчанию,
    выбор того же — сохраняет текущее имя; меню закрывается, звучит `intro`.
  - «Переименовать» `companion-rename` → форма `companion-rename-form`: поле `companion-name-input` (maxlength 20,
    заполнено текущим именем), кнопка `companion-rename-save` (и Enter). Пустое/пробелы — не сохраняется, видна
    ошибка `companion-rename-error` «Имя — от 1 до 20 символов». Успех — меню закрывается, звучит `intro` с новым именем.
  - «Выключить помощника» `companion-off` → `enabled: false`, персонажа и облачка нет, фокус — на `companion-on`.
- **Выключен**: в шапке кнопка «Включить помощника» `companion-on`; включение возвращает прежнего персонажа и имя и
  говорит приветствие (`greeting`/`empty`).
- **Знакомство** `companion-intro` — встроенная карточка (`<section>`) над формой добавления, не модальная, ничего не
  перекрывает. Заголовок `companion-intro-title`: без привычек на момент открытия страницы — «Привет! Я буду помогать
  тебе с привычками. Кого выберешь?», с привычками — «У нас новенький — выбери себе помощника!». 7 кнопок
  `companion-option` (`data-character`, SVG 44 px, имя и вид), кнопка «Позже» `companion-intro-skip` (→ Мурзик).
  После выбора: `{ character, name: имя по умолчанию, enabled: true, introduced: true }`, карточка скрывается,
  звучит `intro`; если фокус был в карточке — переходит на персонажа.
- **Поводы**: при загрузке (если знакомство пройдено и помощник включён) — `greeting` с `{done}`/`{total}` или `empty`,
  если привычек нет; при отметке/снятии сегодняшнего дня кнопкой «Сегодня» или клеткой сегодня — по
  `companionEventForMark` (отметки прошлых дней помощник не комментирует); клик по персонажу — `poke`; после
  знакомства, смены и переименования — `intro`.
- **Хранение**: только `habit-tracker:companion` (JSON настроек); ошибка записи не ломает страницу. `habit-tracker:v1`
  действия с помощником не меняют. Изменение ключа помощника в другой вкладке перечитывается.
- **Подвал**: «Эмодзи и персонажи: Google Noto (CC BY 4.0, Apache 2.0)» — ссылка прежняя (одна), `data-testid` прежний.
- **README**: раздел «Помощник».

## Отклонения и уточнения к плану

1. Дополнительные `data-testid`, не названные в плане: `companion-picker`, `companion-pick` (выбор в меню — отдельный
   testid, чтобы не совпадать с `companion-option` карточки знакомства), `companion-rename-form`,
   `companion-rename-save`, `companion-rename-error`, `companion-intro-title`; у облачка — `data-event`, у кнопки
   персонажа — `data-character`.
2. `companionEventForMark` принимает необязательный `habitId` и возвращает `{ event, ctx }` (а не только строку) —
   чтобы реплика получила название, серию и «осталось».
3. Повод `remaining` выбирается при 1–2 оставшихся привычках (иначе при 2+ привычках поводы `mark`/`markStreak` были бы
   недостижимы). `newRecord` — только при серии ≥ 2 (первая отметка — не «рекорд»).
4. Заголовок карточки знакомства фиксируется при загрузке страницы: добавление привычки до выбора его не меняет.
5. Пока знакомство не пройдено, помощника в шапке нет и приветствия при загрузке нет (реплика `intro` — после выбора).

## На что обратить внимание тестировщику и аудитору

- На чистом localStorage карточка знакомства сдвигает форму добавления вниз (не перекрывает её); облачко помощника
  при узком экране на ~6 с ложится поверх сводки дня, но клики пропускает (`pointer-events: none`).
- Подвал теперь «Эмодзи и персонажи: …» — прежний тест проверяет `toContainText('Эмодзи')`, совместимо.
